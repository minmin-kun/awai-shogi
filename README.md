# あわい将棋

両者が同時に指し手を予約する、ブラウザ用の変則将棋。CPU練習、ルームコードでの友だち対戦、ランダムマッチに対応します。

公開サイトのフッターから`/about`（このサイトについて）へ移動できます。名称・素材の簡易調査の条件と結果は`docs/rights-review-2026-10-22.md`に記録しています。

## ローカル起動

Node.js 24以上。追加パッケージは不要です。

```powershell
cd awai-shogi
npm start
```

http://localhost:3000 を開きます。ルームは `.data/rooms.sqlite` に保存します。`PORT` 環境変数でポート変更可能。別の端末から対戦する場合は、両者が接続できる同じサーバーのURLを使ってください。インターネット向け運用にはHTTPSを設定したホスティングが必要です。

## 確定したルール

- 毎ターン、両者が30秒以内に指し手を同時予約。両者の確定時点で移動開始。未確定のまま時間切れになるとパス。
- 現在の先手、後手の順に実行。先手が1枚以上取ると、次のターンの先手と後手が交代。後手が取っても交代しない。
- 開始後手だけが、対局中一度「二手打ち」ボタンを押して2手を予約できる。同じ駒でも異なる駒でもよい。ただし、1手目に持ち駒から打った駒は2手目では動かせない。自分の移動順に2手連続で実行。ボタンだけでは未消費。2手の確定で消費し、不発でも戻らない。
- 予約時は駒の動く方向・距離、所有者、持ち駒の在庫、成りや行き所のない駒の制限を判定する。移動先・経路の占有や二歩など、先行する移動で変わりうる条件は実行時に判定する。現在は動けないマスも「条件付き予約」として選べる。飛車・角・香の進路が先行手で空けば移動でき、持ち駒も移動先が空けば打てる。実行時にまだ動けなければ不発となり、元の位置と持ち駒は変わらない。取られた駒は復活しない。
- 2手目は自分の1手目が成功したと仮定した盤面で選択する。両者の予約確定後は各手の実行直前に合法性を再判定。1手目が不発で、2手目の予約元にも駒が存在しなければ、2手目も不発になる。予約は駒のIDに結び付け、別の駒が予約元に入っても動かさない。移動先の相手駒が移動していた場合、空きマスへの移動として成立する。
- 王の捕獲で勝利。王手・詰みによる行動制限と打ち歩詰め、千日手・持将棋の自動判定はない。駒の動き、成り・強制成り、持ち駒、二歩、行き所のない駒の制限を実装。
- 二手打ちの先の1手で王を取った場合は即終了し、後続の予約は実行しない。

## 構成と検証

- `src/engine.js`: ブラウザ／サーバー共通のルールエンジン。
- `src/planning.js`: 確定前の予約を巻き戻し、駒・移動先を選び直すための処理。
- `src/realtime.js`: Cloudflare Durable Objectsによる対局・マッチ待機のWebSocket通知、認証、時間切れアラーム。
- `public/transport.js`: WebSocketの自動再接続・要求と応答の照合。
- `src/api.js`: 参加トークンのSHA-256照合、相手の予約を隠すレスポンス、サーバー時刻、競合制御による対局処理。
- `server.mjs`: SQLiteによるローカルサーバー。
- `public/`: レスポンシブUI。練習用CPUは簡単な評価関数を使用。
- `scripts/build.mjs`: Cloudflare Workers用にアセットとエンジンを単一ESMへ組み込み。SitesではD1の`DB`バインディングと `drizzle/` のマイグレーションを使用。

```powershell
npm test
npm run build
```

ルームは24時間有効。参加トークンはブラウザのsessionStorageに保存し、同じタブの再読み込みから復帰可能。対局状態はサーバーに保存。Cloudflare公開ではWebSocketで変更時に通知し、接続中の時間切れはDurable Objectのアラームで解決します。全員が画面を閉じた後は定期実行を止め、再接続時に期限切れのターンを解決します。Node.jsローカルサーバーでは従来のポーリングを使用します。

オンラインの思考時間は各プレイヤーのアニメーション完了通知 (`POST /ready`) 後にサーバー側で30秒を開始します。両者の確定、または各自の時間切れによるパスが揃ってから次のターンへ進みます。通知の再送・再読み込みでは既存の時計を延長しません。切断した画面から完了通知が届かない場合は、10秒の準備猶予後にその側の時計を開始し、対局が停止し続けるのを防ぎます。

予約は実際の駒を動かさず、半透明の駒・番号付き矢印で表示します。二手打ちの2手目は半透明の予約位置から選択できます。取り消しボタンは末尾の1手だけを戻し、2手ある場合は全取り消しも可能です。不発時には理由をイベントと棋譜に保存・表示します。スマートフォンでは基本ルールを折りたたみ、対局開始時にも閉じます。

移動先を選ぶと、予約先の右上付近に「確定」ボタンを表示します。盤の端では盤内に収まるよう位置を補正し、上端では下側へ表示します。ボタンを押すまでは送信しません。二手打ちは2手目の予約先で「2手を確定」と表示し、1手目だけでは確定できません。選び直し・取り消し・送信後は表示を更新または解除します。サイドパネルの確定ボタンも利用できます。旧自動確定の保存設定は参照しません。パスはサイドパネルで確定します。

確定ボタンが表示されている間は、別の自分の駒・持ち駒の選択で古い予約を取り消し、新しい駒の選択に切り替えます。別の移動可能マスを選ぶと、元の予約元から判定し直して移動先を変更します。同じ予約先や無関係なマスでは予約を変更しません。二手打ちの2手目を変更する場合は1手目を維持し、1手目の元の駒を選び直すと依存する2手目も取り消します。成りの選択は新しい移動先で改めて確認します。送信済みの予約は盤上の選択では変更しません。

Cloudflare公開では認証済みWebSocketの接続・切断で通信状態を通知し、接続維持のping/pongは休止対応の自動応答を使用します。接続確認や盤面同期だけでは対局DBへ保存しません。Node.jsローカルサーバーでは認証済みのリクエストで接続を確認し、状態保存は各側3秒間隔を上限として、12秒以上応答がない側を「応答なし」と表示します。切断とバックグラウンドでの通信抑制は区別できないため、切断を断定せず、その可能性を案内します。自分の通信失敗・オフライン・再接続中と、相手の応答状態は分けて表示し、復帰時は自動同期します。通信状態は思考時間や確定済み指し手を変更しません。

公開先のアクセス権と対戦ルーム参加は別です。Sitesの初期公開は所有者限定のため、別アカウントの友だちと試すにはSites側の共有設定も必要です。

歩を打つ指し手が同じ筋の自分の歩と二歩になる場合は、確定前に警告します。警告だけで確定は妨げず、最終判定は実行時に行います。二手打ちの2手目は1手目を反映した盤面で確認し、相手の歩や成った歩は数えません。

「だれかと」→「対局をはじめる」で、同じサーバーの待機中の相手と自動マッチします。開始順はランダムです。相手がいない間は待機し、キャンセルできます。マッチ成立とキャンセルが重なった場合は成立した対局へ進みます。待機情報は同じタブの再読み込みで復帰し、20秒間更新がない待機者は対象から外します。レーティングによる組み合わせは行いません。SQLite／D1共通で既存のroomsテーブルを使用し、追加マイグレーションは不要です。

## Cloudflareへの公開

公開URL: https://play.awai-shogi.workers.dev

`wrangler.jsonc` にCloudflare WorkersとD1の接続先を設定しています。更新時は以下を実行します。

```powershell
npm ci
npm test
npx wrangler deploy
```

初めて操作するPCでは `npx wrangler login --scopes account:read user:read workers:write workers_scripts:write d1:write` で認証してください。DBのスキーマ変更がある場合は、公開前に `npx wrangler d1 migrations apply awai-shogi-db --remote` を実行します。`wrangler deploy` はビルドも実行します。

Cloudflareへの直接公開には `.openai/hosting.json` のSitesプロジェクトとは別のWorker・D1を使用します。既存のSites側のルームは移行されません。Cloudflareの無料枠にはリクエスト・CPU時間・DB容量・読み書き回数の上限があるため、利用量をCloudflareの管理画面で確認してください。

## Cloudflareの通信削減

公開版は対局・マッチ待機の定期HTTPポーリングを使用しません。ルーム作成・参加とマッチ待機の初回だけHTTPを使い、その後の予約確定・時計開始・状態通知・投了はWebSocketで処理します。認証トークンはURLに載せず、最初のメッセージで認証し、サーバーのソケット添付情報にはハッシュのみ保持します。相手に送る通知は従来と同じプレイヤー別ビューで、未公開の予約は送りません。

Durable Objectsは無料プラン対応のSQLiteバックエンドを使用します。タイマーに`setInterval`を使わず、最も近い期限だけをアラームへ予約し、待機中は休止できます。全員が切断したルームは繰り返しアラームを停止します。ローカル統合検証では40ターンを両側の時計開始と予約確定の合計160回の対局DB更新で処理し、pingや状態同期では対局DBのrevisionが増えないことを確認しています。これはDOのアラーム操作などを含む総書き込み数ではなく、1日300〜500局の見込みは本番負荷試験による保証ではありません。

静的ファイルは`dist/client`へ出力しCloudflare Workers Static Assetsから配信します。`/api/*`だけWorkerを先に実行します。`npm test`はビルドの後、ルール・APIとMiniflare上のWebSocket統合テストを実行します。公開時にはWranglerがDurable Objectの初回マイグレーションも適用します。Node.jsでの`npm start`ではポーリング方式のまま動作します。

## 対局通知の差分化

`public/room-updates.js` の共通コーデックをサーバーとブラウザで使用します。認証時に `room-delta-v1` を指定した接続だけ差分を受信し、従来の接続には全体ビューを返します。初回認証、再接続、明示的な `sync` は必ず全体スナップショットです。通常の更新は変更された状態項目・盤面のマス・追加された棋譜だけ送ります。

ソケットごとの連番と差分元の連番、ルーム・プレイヤー、棋譜の追加位置を検証します。不一致の差分は途中まで適用せず破棄し、全体スナップショットを要求します。応答を確認できない指し手を自動で再送しません。通信層は描画層に独立したコピーを渡すため、駒のアニメーションで次の差分の基準状態を壊しません。

休止中も小さな基準状態をソケット添付情報に保持します。過去の棋譜自体は保持せず、件数とSHA-256のダイジェストだけ保持し、過去の棋譜が書き換わった場合は全体を送ります。差分化による対局DBへの追加保存はありません。

300ターンのパス対局で、復元後の全状態が各ターンの元データと一致することを確認し、更新ごとに全体を送る比較では合計5,999,123 bytesから108,037 bytesへ約98.2%削減しました。これは特定条件でのJSONデータ量の比較で、WebSocket・TLS等のヘッダー、初回同期・再同期は含まず、実際の指し手や棋譜の長さにより削減率は異なります。

## セキュリティ制限

Cloudflareのレート制限バインディングで、同じIPからのAPI全体を240回/分、ルーム作成を10回/分、参加・マッチング操作を合計30回/分、WebSocket接続試行を30回/分に制限します。これはCloudflare拠点ごとの近似制限です。同じ回線を使う人は枠を共有します。ローカルのNodeサーバーやバインディングのないテスト環境では、件数を制限したメモリ内カウンターを使用します。

各Durable Objectの接続上限は同じIPで6本、同じ参加情報で4本、ルーム全体で12本、マッチング全体で128本です。WebSocketの操作は接続ごとに100回/10秒、全体再同期とマッチング操作は10回/10秒を上限とし、超過時は接続を閉じます。カウンターはソケット添付情報に保持するため、休止から復帰しても引き継ぎ、D1への書き込みは増えません。マッチ成立の通知は成立した対局の参加者だけに送ります。

HTTP本文とWebSocketメッセージはUTF-8で8KiBまでです。HTTPはストリームの実バイト数を数え、Content-Lengthの省略・偽装に依存せず制限し、圧縮本文は受け付けません。JSONの形式も検証します。未認証の接続は10秒以内に認証がなければ閉じ、認証前のDOメタデータ保存やアラーム登録は行いません。

静的配信にはビルド時に生成した`_headers`、APIとローカル配信には共通関数で、CSP、埋め込み禁止、MIME判定の固定、Referrer非送信、HSTS等のヘッダーを付けます。外部OriginからのAPIアクセスも拒否します。これらは不正利用を抑える対策であり、分散した攻撃やWorker呼び出し自体の無料枠消費を完全に防ぐものではありません。

ルームコードはDBへのINSERTで確保し、重複時は最大8回まで作り直します。ランダムマッチの復帰時にも実際のルームの参加キーを照合するため、旧形式のマッチ情報でコードが衝突していても別対局の状態は返しません。

マッチ成立後の復帰情報は`MATCH_<参加キーのハッシュ>`という独立したレコードに24時間保存します。両者の復帰情報を保存するまでは共有キューに引き継ぎ情報を残し、保存途中の失敗でも組み合わせを維持します。共有キューは最大256件で、満杯なら新規参加を一時拒否します。旧形式の成立情報は復帰時に移行します。同時更新が競合した際に作成だけ済んだ未使用ルームは、期限切れ削除の対象になります。

`0001_expiry_index.sql`で有効期限の索引を追加します。Cloudflareでは毎時15分（UTC）に、期限切れのルームと復帰情報を最大500件削除します。既存の期限で参照を拒否し、物理削除は負荷を抑えて段階的に進めます。Nodeサーバーも起動時と毎時に同じ削除を実行します。公開時は先に`npx wrangler d1 migrations apply DB --remote`を適用してください。

対局は1,000ターンで引き分けとし、以降の棋譜追加を止めます。上限ターンで王を取った場合は勝利を優先します。このルールはCPU戦とオンライン戦で共通です。

## 利用上限の表示

D1の日次読み書き上限・保存容量上限を認識した場合は、HTTPとWebSocketに共通の`SERVICE_QUOTA_EXCEEDED`を返します。通常の429（操作回数制限）や原因不明の503は区別し、利用上限と断定しません。WebSocketの接続確立に失敗した場合は、DBを参照しない`GET /api/status`を一度確認し、Cloudflareの1027ページが取得できた場合も日次上限として扱います。ブラウザやネットワークが応答自体を取得できない場合は、原因を特定できません。

上限確認時は専用モーダルを表示して自動再試行を止め、参加情報はsessionStorageに残します。日次上限では次のUTC午前0時を日本時間に換算して表示し、容量上限では時刻を案内しません。時間経過後は利用者が再読み込みします。時計は確認不能として「—」表示に切り替えますが、サーバー上の対局時間を停止する処理ではなく、対局再開を保証しません。通常の一時障害でも保存済み参加情報は消さず、認証失敗・ルーム期限切れが確認できた場合に削除します。
